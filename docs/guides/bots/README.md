# TheOne Skill 型 Bot 接入文档 · v1

这份文档可直接交给另一个开发会话。目标是交付一个能导入 TheOne 的 Bot，而不是另做网页或聊天后台。

Bot 是配好职责和技能的助手；Skill 是告诉助手如何完成任务的操作手册。例如“机票 Bot”挂载“订机票 Skill”，由 TheOne 已配置的模型理解要求，再用已接入的工具执行。Skill 本身不会自动提供网站访问、电脑操作或外部服务权限。

## 最快接入

1. 复制本目录的 [writing-bot](./writing-bot/) 示例，修改 `bot.json` 和 `skills/writing/SKILL.md`。
2. 在 TheOne 左侧打开 **Bot 广场 → 导入 Bot**。
3. 选择包含 `bot.json` 的本地文件夹，或粘贴公开 GitHub 仓库/文件夹链接。
4. 查看 Bot 名称、技能、所需工具和来源，确认信任来源后导入。
5. 点击 **使用 Bot**，选择工作文件夹，使用已配置模型开始聊天。开场问题只填入草稿，不会自动发送。

现有 Skill 只需原样放进 `skills/` 下，并增加 `bot.json`，不必重新开发模型服务。本版接受 Bot 包，不会擅自把任意只有 SKILL.md 的仓库猜成一个 Bot。

TheOne 内置的 **作图助手** 已按同一 Bot 包格式接入 Bot 广场。它使用设置中已配置的真实图像模型和 `aionui_image_generation` 工具；没有配置时会明确提示，不会用占位图片或纯提示词冒充完成。标准包示例见 [image-generation-bot](./image-generation-bot/)。

## 交付文件

```text
my-bot/
├── bot.json
├── README.md                 # 建议：用法、依赖、数据来源
├── LICENSE                   # 建议：你的代码/技能的再使用许可
└── skills/
    ├── book-flight/
    │   ├── SKILL.md
    │   ├── scripts/          # 可选：任务脚本
    │   ├── references/       # 可选：规则和说明
    │   └── assets/           # 可选：合法且完整的素材
    └── compare-flights/
        └── SKILL.md
```

`bot.json` 是结构化配置文件，相当于 Bot 的名片。TheOne 用它决定广场如何展示、应挂载哪些 Skill。

```json
{
  "schemaVersion": 1,
  "id": "my.flight-bot",
  "name": "机票助手",
  "version": "1.0.0",
  "description": "按照我的订票流程查找、比较并协助预订机票。",
  "author": "你的名字",
  "instructions": "使用挂载的技能处理机票任务。缺少信息时询问用户；无法执行时明确说明，不编造航班、价格或订单。",
  "skills": ["skills/book-flight/SKILL.md", "skills/compare-flights/SKILL.md"],
  "requiredCapabilities": ["files", "shell", "computer-use"],
  "tags": ["出行"],
  "starters": ["帮我查找下周五上海到北京的机票"]
}
```

上面是配置格式示例，不包含特定航空公司的订票流程。安装并启动 Cua Driver、授予 macOS“辅助功能”和“屏幕录制”权限后，TheOne 会提供真实的 `computer-use` 工具；驱动未就绪时，依赖该能力的 Bot 会标记缺少工具并阻止新建执行会话。

| 字段                 | 必填 | 规则                                                                            |
| -------------------- | ---- | ------------------------------------------------------------------------------- |
| schemaVersion        | 是   | 固定数字 `1`，表示接入规范版本                                                  |
| id                   | 是   | 稳定唯一标识，最多 80 字符；小写字母开头，只含小写字母、数字及段间的 `.` 或 `-` |
| name                 | 是   | 广场显示名称，最多 80 字符                                                      |
| version              | 是   | `1.0.0` 这样的三段版本号，可带 `-beta.1` 后缀，最多 40 字符                     |
| description          | 是   | 功能介绍，最多 500 字符                                                         |
| instructions         | 否   | Bot 整体职责与规则，最多 16000 字符；与 Pi 原有指令一起使用                     |
| skills               | 是   | 1–20 个相对路径，每个以 `skills/` 开头、以 `/SKILL.md` 结尾；不能重复           |
| requiredCapabilities | 否   | `files`、`shell`、`computer-use`；默认 `["files"]`                              |
| tags                 | 否   | 0–8 个分类标签，每个最多 30 字符                                                |
| starters             | 否   | 0–6 个开场问题，每个最多 500 字符                                               |
| author               | 否   | 作者，最多 100 字符                                                             |

未知字段会被拒绝，避免拼错字段后悄悄失效。不要在配置中放密钥、登录凭据、机器绝对路径或自动安装命令。

## Skill 格式

`SKILL.md` 是普通文字文件，上方用两行 `---` 包住名称与简介，下方写执行步骤：

```markdown
---
name: book-flight
description: 查询和比较航班，并按用户确认的选择协助预订机票。
---

# 订机票

1. 确认出发地、目的地、日期、乘机人数与预算。
2. 检查必要工具和真实数据来源；缺少时说明，不生成替代结果。
3. 按已接入渠道获取航班信息，列出完整价格、行李额度和退改条件。
4. 按任务需要请用户确认选择及后续操作。
```

- `name` 必须是小写字母、数字和单个连字符组成，最多 64 字符，同一 Bot 中不能重名。
- `description` 必须非空，最多 1024 字符；正文必须有内容。
- 本版不接受 `disable-model-invocation: true`，因为 Bot 需要由模型调用这些技能。
- 名称建议与父目录一致。附带脚本、参考资料和素材应放在该 Skill 自己的目录内，引用路径相对于 SKILL.md 所在目录。
- 文件夹导入会复制整个已声明 Skill 的目录；未声明的 Skill、仓库其他文件和依赖目录不会自动导入。
- 最多 200 个文件、每个 2 MB、总计 20 MB。不接受隐藏路径、符号链接、仓库子模块或包含 `..` 的路径。
- 脚本不会在导入时运行，也不会自动安装依赖；需要额外程序或账号时，在 README 和 Skill 中写明。脚本可由模型通过现有命令工具调用，例如 `bash scripts/task.sh`，不要依赖文件的可执行位。

## GitHub 导入

GitHub 是代码托管网站。你可以把 Bot 放在一个仓库中，把地址交给 TheOne，无需先手工下载。

支持以下公开链接：

```text
https://github.com/OWNER/REPOSITORY
https://github.com/OWNER/REPOSITORY/tree/main/path/to/my-bot
https://github.com/OWNER/REPOSITORY/tree/COMMIT_ID/path/to/my-bot
```

仓库链接默认读取默认分支根目录的 `bot.json`；文件夹链接读取该文件夹的 `bot.json`。分支名包含 `/` 时会尝试解析现有分支。导入会先固定到一个提交版本，再下载文件，避免导入过程中远端更新造成文件版本混用。广场记录来源提交地址。

本版不支持私有仓库登录、任意下载网址、GitHub 文件页面的 `blob` 链接或安装依赖脚本。GitHub 限流时可稍后重试，或自己下载后导入本地文件夹。TheOne 不会将 ChatGPT 凭据发送到 GitHub。

仅导入你自己拥有或已获许可使用的内容；公开可访问不代表允许复制和重新发布。根目录的 LICENSE / LICENSE.md 与 README.md 会一并保留。

## 模型、会话和工具

- **模型**：复用 TheOne 设置里的默认模型与凭据。Bot 包无需包含密钥。聊天中可按现有方式切换模型。
- **技能加载**：为 Bot 会话传入明确的 Skill 路径，关闭普通技能目录自动发现；Bot 职责追加到 Pi 指令中。Pi 会在任务相关时读取对应 SKILL.md，不会把 Skill 当作硬编码回答。
- **工作文件夹**：用户启动时选择，作为本次任务的文件工作位置，不从 Bot 包指定机器路径。
- **对话隔离**：每次点击使用并选定文件夹，会创建独立会话；旧对话从左侧历史打开。普通聊天不会挂载 Bot 的技能。
- **版本保持**：每个会话绑定导入文件的内容指纹，指纹是用于识别完整文件版本的一串校验字符。导入同一个 id 的新版只改变广场的新会话，旧会话和分支继续使用旧版。
- **恢复与移除**：重启恢复绑定；分支继承绑定；移除广场条目不删除聊天或旧版文件，旧会话仍可继续使用。重复导入可以恢复条目。

工具声明的含义：

| 标识         | 当前状态         | 含义                                                         |
| ------------ | ---------------- | ------------------------------------------------------------ |
| files        | 已接入           | Pi 的文件读取和修改工具                                      |
| shell        | 已接入           | Pi 的命令执行工具，类似让助手在终端输入命令                  |
| computer-use | 已接入（需配置） | 通过 Cua Driver 看屏幕、点击和输入；只有驱动存在时才报告可用 |

`requiredCapabilities` 是启动前的依赖检查，不是权限隔离机制，也不会安装工具。工作文件夹不是文件访问的安全边界；当前 Pi 的命令工具具备本机进程已有权限。不要把不信任来源的 Skill 当成纯文档导入使用。

TheOne 启动时把 `computer` 与 `jev_judge` 两个工具注册到 Bot 会话的 Pi 进程。`BotStore` 只在检测到 Cua Driver 时报告 `computer-use`；自动测试还会检查真实 Pi 模型请求中是否包含这两个工具，而不是只检查能力字符串。

Computer Use 的执行规则：先观察，再执行一个小动作，然后重新观察。涉及候选方案（例如选航班）时，先收集符合用户要求的事实并调用 Jev 判断，再进入所选方案。Jev 只负责比较和风险判断，不等于用户授权；付款、最终订票、发送消息、删除和其他不可撤销动作必须由用户确认。

## 给另一个开发会话的交付要求

交付一个文件夹或公开 GitHub 链接，包含：

1. 符合 v1 的 bot.json，明确实际所需工具。
2. 所有声明的 SKILL.md 及其完整配套脚本、资料和素材。
3. README：用途、使用示例、必要账号或环境依赖、已验证范围和限制。
4. 许可证及外部素材的使用授权说明。
5. 至少一次真实流程验证记录；不能用模拟订单、虚构商品数据或假回复冒充完成。

## TheOne 内部接入方法（应用开发者）

下面是应用界面和桌面主程序之间的方法，不是对外开放的网络接口。外部 Skill 不需要也不能直接访问它们。

| 方法        | 输入                                           | 返回                                                                  |
| ----------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| bots        | 无                                             | 已导入条目、版本、收藏状态、缺失工具                                  |
| botPreview  | `{ github: "https://github.com/..." }` 或 `{}` | GitHub 读取结果，或打开本地目录选择；返回预览及短期 token，取消返回空 |
| botInstall  | `{ token }`                                    | 安装已预览的原始文件，返回条目；token 10 分钟过期                     |
| botDiscard  | `{ token }`                                    | 丢弃预览                                                              |
| botFavorite | `{ id, favorite }`                             | 保存收藏状态                                                          |
| botRemove   | `{ id }`                                       | 移除广场条目，保留会话使用的包                                        |
| create      | `{ cwd, botId }`                               | 新建 Bot 会话，后续沿用现有 send / open / fork 方法                   |

Bot 列表与会话绑定保存在应用数据目录的 `bots/state.json`，导入文件保存在 `bots/packages/内容指纹/`。聊天正文仍仅由 Pi 会话文件保存，不另建一套聊天历史。

### 不选择工作文件夹

使用 Bot 时可点“直接开始对话”，无需选择文件夹；也可点“选择文件夹新建”处理指定项目。未选文件夹的对话在应用数据目录中使用各自独立、持久保存的工作目录，重启后仍能恢复。普通聊天同样支持直接新建。
